# 🚀 Project Reboot
### Project Management Simulation — Recovering a Delayed & At-Risk Digital Project

> **The project is already in trouble. You're the Project Manager brought in to turn it around.**

---

## 📌 Project Overview

**Project Reboot** is a project management simulation based on the recovery of a delayed digital banking project.

The fictional project, **SmartSpend**, is designed to help customers:

- Categorise monthly spending
- Set personalised spending limits
- Track expenses
- Receive spending alerts

Midway through the project, several challenges emerge:

- Timeline delays
- Budget pressure
- Changing requirements
- Limited resources
- Stakeholder misalignment
- Compliance dependencies

The Project Manager is given **30 days to stabilise the project and prepare it for a controlled launch.**

---

## 🎯 Project Objective

The objective of Project Reboot is to develop and demonstrate a structured approach to recovering an at-risk project.

The project focuses on:

**Scope Management → Planning → Stakeholder Management → Risk Management → Change Management → Project Monitoring**

## 🧩 Project Challenges

The project currently faces:

🔴 **Timeline Delays**  
The project is behind its original schedule.

🟠 **Changing Requirements**  
New requirements create potential scope creep.

🟠 **Resource Constraints**  
Limited engineering resources affect critical activities.

🟠 **Stakeholder Misalignment**  
Different teams require better alignment on priorities and decisions.

🟠 **Compliance Dependencies**  
Compliance approval is required before launch.

---

## 🛠️ Project Management Approach

The recovery strategy follows four stages:

### 1. Assess

Understand the current project health, issues, risks and constraints.

### 2. Align

Prioritise requirements and align stakeholders around the revised scope.

### 3. Recover

Execute critical recovery activities while managing risks, issues and dependencies.

### 4. Launch Ready

Prepare the project for testing, approvals and controlled launch.

## 🔄 Project Management Scenario

During the recovery phase, a new change request is introduced.

The Marketing Team requests an additional social-sharing feature for SmartSpend.

Instead of automatically accepting or rejecting the request, the Project Manager:

1. Documents the change.
2. Assesses scope impact.
3. Assesses timeline impact.
4. Reviews resource requirements.
5. Evaluates project risk.
6. Presents options to stakeholders.
7. Records the decision.
8. Updates the project plan if required.

This demonstrates the importance of **structured change control in project management.**

## 💡 Key Learning

Project recovery is not simply about completing tasks faster.

It requires balancing:

**Scope + Time + Resources + Risk + Stakeholders**

A Project Manager must continuously evaluate these factors and make structured decisions as the project changes.

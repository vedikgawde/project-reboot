# Project Reboot
## Project Brief

### Project Overview

Project Reboot is a project management simulation focused on recovering a delayed and at-risk digital project.

The project has experienced timeline delays, budget pressure, changing requirements, and stakeholder misalignment. A new Project Manager has been assigned to assess the situation, identify the major issues, and create a structured recovery plan.

### Business Scenario

A financial services company is preparing to launch a new digital banking feature called **SmartSpend**.

SmartSpend is designed to help customers:
- Categorise their monthly spending
- Set personalised spending limits
- Track their expenses
- Receive alerts when they are approaching their limits

The project was initially planned for a 60-day delivery period. However, midway through the project, several issues have caused delays and increased project risk.

### Current Project Situation

| Area | Current Status |
|---|---|
| Timeline | Behind schedule |
| Budget | Under pressure |
| Scope | Requirements are changing |
| Stakeholders | Not fully aligned |
| Resources | Limited |
| Overall Project Health | At Risk |

### Project Manager's Challenge

The Project Manager has 30 days to stabilise the project and prepare it for a controlled launch.

The key objectives are to:

1. Identify the major project issues.
2. Reassess project scope and priorities.
3. Create a realistic recovery plan.
4. Align key stakeholders.
5. Identify and manage project risks.
6. Establish clear ownership of tasks.
7. Manage new change requests.
8. Define measurable project success criteria.

### Key Stakeholders

- Project Manager
- Product Manager
- Engineering Team
- UX/UI Team
- Compliance Team
- Finance Team
- Marketing Team
- Senior Management

### Project Objective

To recover the SmartSpend project by creating a structured 30-day project recovery plan that addresses schedule, scope, resources, risks, stakeholder alignment, and change management.

### Success Criteria

The project will be considered successfully recovered when:

- Critical project tasks have clear owners.
- Priority requirements are agreed upon.
- Major risks have mitigation plans.
- Stakeholders have a defined communication process.
- The revised timeline is realistic and approved.
- The project is prepared for a controlled launch.

# Project Reboot
## Project Charter

### 1. Project Name

**SmartSpend — Project Recovery & Controlled Launch**

### 2. Project Manager

Project Manager — Project Reboot

### 3. Project Background

SmartSpend is a proposed digital banking feature designed to help customers monitor their spending and set personalised spending limits.

The project was originally planned for a 60-day delivery period. Midway through execution, delays, changing requirements, limited resources, and stakeholder misalignment created a risk to the planned launch.

Project Reboot has been initiated to stabilise the project and establish a realistic path toward launch.

### 4. Business Need

The project needs a structured recovery approach to prevent further delays, control scope changes, improve stakeholder alignment, and ensure that critical product requirements are prioritised before launch.

### 5. Project Objective

To recover the SmartSpend project within a 30-day recovery phase by:

- Re-establishing project priorities.
- Clarifying scope and requirements.
- Assigning ownership for critical activities.
- Addressing key risks and issues.
- Improving stakeholder communication.
- Creating a realistic recovery timeline.
- Preparing the product for controlled launch.

### 6. Project Scope

#### In Scope

- Review of existing project status.
- Requirement prioritisation.
- Project schedule recovery.
- Stakeholder alignment.
- Risk and issue management.
- Resource planning.
- Change request management.
- Testing and launch readiness planning.
- Project reporting.

#### Out of Scope

- Development of unrelated product features.
- Major redesign of the existing product.
- Expansion into new markets.
- Long-term product strategy after launch.
- Post-launch feature development.

### 7. Key Deliverables

| Deliverable | Description |
|---|---|
| Recovery Plan | 30-day plan to stabilise the project |
| Prioritised Requirements | Agreed list of critical requirements |
| Revised Timeline | Updated project schedule |
| RACI Matrix | Defined ownership and responsibilities |
| RAID Log | Tracking of risks, assumptions, issues and dependencies |
| Change Request | Formal process for handling new requirements |
| Launch Readiness Plan | Activities required before launch |

### 8. Key Stakeholders

| Stakeholder | Role |
|---|---|
| Project Manager | Overall project coordination |
| Product Manager | Product requirements and priorities |
| Engineering Team | Technical development |
| UX/UI Team | User experience and interface |
| Compliance Team | Regulatory and compliance review |
| Finance Team | Budget and financial oversight |
| Marketing Team | Launch communication |
| Senior Management | Strategic decisions and approvals |

### 9. High-Level Constraints

- 30-day recovery window.
- Limited project resources.
- Existing budget pressure.
- Changing requirements.
- Dependencies between multiple teams.
- Compliance and approval requirements.

### 10. High-Level Risks

- Further timeline delays.
- Scope creep.
- Resource availability issues.
- Delayed stakeholder decisions.
- Compliance-related delays.
- Technical dependencies affecting delivery.

### 11. Success Criteria

The project recovery will be considered successful when:

- Critical requirements are prioritised and approved.
- Project responsibilities are clearly assigned.
- Major risks and issues have owners and action plans.
- Stakeholder communication is structured.
- A revised timeline is agreed upon.
- The project is ready for controlled launch.

### 12. Project Approval

This charter establishes the initial direction for Project Reboot and provides the foundation for detailed planning, risk management, stakeholder coordination, and project recovery activities.

**Project Status:** At Risk  
**Recovery Duration:** 30 Days  
**Project Type:** Digital Product Launch
